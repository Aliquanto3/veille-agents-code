## Intent

**Problem :** aucune Architecture ne permet de mesurer l'effet de la réécriture HyDE sur la recherche dense (FR-20) : on ne peut pas chercher avec le vecteur d'une réponse hypothétique, ni mesurer ce que cette réponse coûte.

**Approach :** nouvelle Architecture `hyde`, sous-classe de `NaiveRag` (même index dense : chunker, embedder, store). Dans `answer`, un appel `complete` au rôle `hyde` (step `hyde`) produit la réponse hypothétique. Son vecteur `embed_queries`, éventuellement moyenné avec celui de la Question puis renormalisé (`mix_question`), est passé au Retriever via `query_vector`. Le Contexte et la génération restent ceux de `naive_rag`.

## Boundaries & Constraints

**Always :**
- Enregistrement `@register("architecture", "hyde")`, `name = "hyde"`, mêmes `capabilities` que `naive_rag` (`incremental_update=True`, `retrieval_method="ranked"`).
- Params hérités de `NaiveRag.Params`, plus `mix_question: bool = False`, `hyde_model: Annotated[str | None, ModelRefMeta("generator_models[0]")] = None` (pas `answer_producer`) et `hyde_max_tokens: int = Field(default=256, gt=0)`.
- `query_params = {"k", "mix_question", "hyde_model", "hyde_max_tokens"}` : changer ces valeurs réutilise l'index.
- La requête `hyde` passe par `self.ctx.gateway.complete` : `LLMRequest(model_id=..., role="hyde", step="hyde", system=<consigne en français>, messages=(Message(role="user", content=question.text),), max_tokens=hyde_max_tokens, seed=ctx.seed, inputs={"text": question.text})`. Le poste `query` est fixé par l'appelant (`ctx.scope`), jamais par l'Architecture.
- L'Architecture ne trace jamais : le span `hyde` vient de la passerelle, le span `embed` de l'Embedder.
- La réponse hypothétique sert uniquement à calculer le vecteur. Elle n'est jamais transmise au `context_builder`, au `generator` ni à `build_arch_answer`.
- `build_arch_answer(..., tokenizer=self.ctx.tokenizer_for(self.generator.model_id))` et `embedder_dim()` sont hérités sans changement.

**Never :**
- Modifier `naive_rag.py` (sauf pour un éventuel point d'extension minimal et sans effet sur son comportement), `roles.py`, `fake.py`, le runner, la passerelle ou le Rapport. Le rôle `hyde` existe déjà, et le Faux LLM renvoie par défaut les 30 premiers mots de `text`.
- Faire entrer la réponse hypothétique dans la clé d'index, ou partager physiquement le cache d'index de `naive_rag` : la clé contient le nom de l'Architecture.
- Utiliser un réseau ou un LLM réel dans les tests.

**Acceptance Criteria :**
- Given l'Architecture `hyde` construite sur le même index dense que `naive_rag`, when on répond à une Question, then la passerelle reçoit une requête `role="hyde"`, `step="hyde"` dont le span porte `wl.post = "query"` et diffère du span `generate`, and le Retriever reçoit en `query_vector` le vecteur `embed_queries` de la réponse hypothétique.
- Given `mix_question: true`, when on répond, then le vecteur de recherche est la moyenne renormalisée (norme 1) des vecteurs de l'hypothèse et de la Question, and `"mix_question" in Hyde.query_params`.
- Given la Réponse produite, when on inspecte `context_texts` et les Citations, then aucun bloc ne contient la réponse hypothétique, and chaque Citation désigne un Ancrage d'un Passage retrouvé.
- Given une réponse hypothétique scénarisée qui reprend le texte d'un Passage précis, when on répond, then ce Passage est au rang 1.

## Design Notes

```python
def _vecteur(self, question):
    hyp = self._hypothese(question).strip() or question.text
    if not self.params.mix_question:
        return self.embedder.embed_queries([hyp])[0]
    v_h, v_q = self.embedder.embed_queries([hyp, question.text])
    somme = v_h + v_q
    norme = float(np.linalg.norm(somme))
    return (somme / norme).astype(np.float32) if norme > 0 else v_h
```

Un seul appel `embed_queries` par Question, donc un seul span `embed` au poste `query`. Le coût HyDE se lit alors sur les spans `hyde` et `embed`.

## Décisions prises sans l'utilisateur

- « Même index que `naive_rag` » : `Hyde` hérite de `NaiveRag` (index, update, load identiques). Option écartée : partager physiquement le cache, ce qui est impossible car le nom de l'Architecture entre dans la clé.
- Modèle du rôle `hyde` : champ `hyde_model` qui prend par défaut `generator_models[0]`, sans `answer_producer`. Options écartées : réutiliser le modèle du Generator sans champ dédié ; marquer le modèle comme producteur de Réponse.
- `hyde_max_tokens = 256`. Option écartée : reprendre `max_tokens` du Generator (1024), trop large pour un court passage hypothétique.
- `hyde_model` et `hyde_max_tokens` sont mis dans `query_params`. Option écartée : les laisser dans la clé d'index, ce qui forcerait une réindexation sans raison.
- Hypothèse vide : repli sur le texte de la Question. Option écartée : lever une erreur, ce qui ferait échouer une Question pour une sortie libre vide.
- Moyenne de norme nulle : repli sur le vecteur de l'hypothèse. Option écartée : repli sur la Question.
- Mélange : un seul appel `embed_queries([hyp, question])`. Option écartée : deux appels, donc deux spans `embed`.
- Configuration `hyde` dans `experiments/mini-test.yaml`, `tests/conformance/test_architectures.py` et `tests/e2e/test_sm3.py` : non traités, car ces fichiers sont absents du dépôt (story 4.14 non livrée, comme reporté en 6.2). Option écartée : les créer dans cette story.
