## Intent

**Problem:** Aucune Architecture ne précharge tout le Corpus dans le cache de prompt. On ne peut donc pas mesurer le coût et la qualité d'une approche sans recherche dont le coût d'indexation est explicite (FR-22).

**Approach:** Créer l'Architecture `cag`, qui hérite de `long_context`. Son `load` émet, au poste `indexing`, un appel de préchargement dont le system est identique à celui de `generate` (`cache_system: true`). Les Questions suivantes lisent alors ce préfixe en cache.

## Boundaries & Constraints

**Always :**
- Enregistrement `("architecture", "cag")`, avec `capabilities = ArchCapabilities(retrieval_method="cited", full_corpus_in_prompt=True, requires_prompt_cache=True)`.
- `index` écrit `passages.jsonl`, un Passage par Ancrage, comme `long_context`.
- Le préchargement a lieu dans `load` uniquement. Le chemin « index construit » et le chemin « index servi par le cache » sont donc identiques.
- L'appel de préchargement est octet pour octet le même préfixe que `generate` : même rôle `generate` (donc même marqueur), même system `_SYSTEM + "\n\nContexte :\n" + context.text`, même schéma `GenerateOutput` (donc mêmes `tools` chez Anthropic). Seuls diffèrent l'étape `cag.preload` et le message user.
- `check(profile)` : on reprend celui de `long_context` (fenêtre + sortie, palier, `token_factor`). Il n'émet aucun appel.
- Les seuls spans sont ceux de la passerelle. L'Architecture ne trace rien.

**Never :**
- Modifier le runner, la passerelle (`llm/gateway.py`), `IndexCache`, le Rapport ou `config/validate.py`. Le refus `prompt_cache: false` existe déjà (story 1.6, `validate.py:72`).
- Comparer le Corpus à `min_cacheable_tokens` dans `cag`. Un préfixe trop court est accepté sans erreur, et c'est le fournisseur qui rend 0 token en cache.
- Ajouter un rôle LLM, un repli par recherche, ou mettre le cache du system dans `answer_with_context`.

## Design Notes

Pourquoi le rôle `generate` et le même schéma : la passerelle préfixe le system par `[[wl:role=…]]` et Anthropic place `tools` avant `system` dans le préfixe en cache. Un autre rôle ou un appel `complete` sans schéma produirait un préfixe différent, donc aucune lecture en cache.

Cache de réponses : un second `wl run` sert le préchargement depuis le cache de réponses, sans appel au fournisseur. Q1 écrit alors le cache et Q2 le lit, et l'AC 2 (seconde Question) tient dans les deux cas.

```python
def load(self, directory: Path) -> None:
    super().load(directory)
    self.generator.preload(self._contexte)  # poste fixé par le runner (AD-8)
```

## Décisions prises sans l'utilisateur

- `Cag` hérite de `LongContext` (check, index, answer réutilisés) ; écarté : une classe autonome qui duplique `check`.
- Préchargement par une nouvelle méthode `LLMGenerator.preload`, qui garantit un system identique ; écarté : construire la requête dans `cag.py` en dupliquant `_SYSTEM`.
- Préchargement en rôle `generate`, étape `cag.preload`, via `complete_structured(GenerateOutput)` ; écartés : un nouveau rôle `preload` (marqueur différent, donc pas de lecture en cache) et `complete` sans schéma (`tools` absents, donc préfixe différent chez Anthropic).
- `max_tokens` du préchargement = celui du Generator ; écarté : `max_tokens` minimal, qui risquerait une sortie d'outil tronquée et donc non conforme.
- Generator autre que `llm` refusé à la construction (`ConfigError`), comme `hyde` et `corrective_rag` ; écarté : ignorer le préchargement sans le dire.
- `min_cacheable_tokens` n'est pas vérifié par `cag`, et l'AC « Corpus court » est testé avec un provider de test qui rend 0 token en cache ; écartés : modifier `FakeProvider`, ou `build_providers` dans la passerelle (interdit).
- Après une mise à jour, le préchargement est imputé au poste `update`, choisi par `IndexCache.build(post=...)` ; écarté : forcer `indexing` dans l'Architecture.
- Configuration `mini-test.yaml`, conformance et SM-3 reportées tant que la story 4.14 n'est pas livrée ; écarté : créer ces fichiers ici, ce qui sortirait du périmètre.
