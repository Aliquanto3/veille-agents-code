## Intent

**Problème :** rien n'empêche aujourd'hui de lancer une Exécution sur un Jeu d'évaluation modifié en douce. La partie test n'est pas non plus mise à part (FR-13, SM-C2, AD-15).

**Approche :** un nouveau module `evalset/freeze.py` et la commande `wl questions geler`. Le module répartit les Questions validées ou corrigées entre dev et test, avec une stratification par `type` et un tirage déterministe par la graine. Il écrit `freeze = {sha256, at, seed, dev_ratio}` et fournit `verify_frozen` et `select_questions`, dont le runner de l'epic 4 se servira.

## Boundaries & Constraints

**Toujours :**
- Empreinte : `hashlib.sha256(canonical_json(d).encode("utf-8")).hexdigest()`, soit 64 caractères hexadécimaux. `d` est obtenu à partir de `doc.model_dump(mode="json")`, auquel on retire la clé `freeze` et, dans chaque Question, la clé `contaminated_by`. Le champ `split` reste dans l'empreinte.
- Questions participantes : statut `validated` ou `corrected`. Les `rejected` reçoivent `split: null`.
- Stratification : pour un Type de `n` Questions participantes, `n_dev = math.floor(n * dev_ratio + 0.5)`, arrondi au plus proche avec les demis vers le haut. Cette formule figure dans la docstring. On trie les ids du Type, on mélange la liste avec `random.Random(int(sha16(str(seed), "split", type), 16))` (le même tirage que `ctx.rng("split", type)`, AD-20, sur le modèle de `corpus/tiers.py:38`), et les `n_dev` premiers vont en dev. Le `split` déjà présent dans le fichier n'a aucune influence sur la répartition.
- `at` est l'heure UTC au format `AAAA-MM-JJTHH:MM:SSZ`. Il n'entre ni dans l'empreinte ni dans la répartition.
- Les erreurs sont des `ConfigError` rédigées en français. La CLI les convertit en code de sortie 2 (contracts §8). Le module ne dépend que de `core` et `evalset.io`, sans `Context` ni `run.lock`.

**Jamais :**
- Pas de modification du runner, du Rapport ni de `io.py` : `Freeze` et `QuestionsFile` y existent déjà.
- Aucun gel partiel et aucune écriture du fichier en cas de refus.
- Pas de Jeu de référence du Mini-corpus : c'est la story 3.7.

## I/O & Edge-Case Matrix

| Scénario | Entrée / état | Résultat attendu | Erreur |
|---|---|---|---|
| Gel nominal | 50 `validated`, 5 Types × 10, ratio 0,4, graine 42 | 4 dev et 6 test par Type, `freeze` rempli | — |
| Regel | même contenu, même graine | répartition et `sha256` identiques | — |
| Questions `generated` | au moins une `generated` | rien n'est écrit, les ids sont listés | `ConfigError`, code 2 |
| Rien à geler | aucune `validated` ni `corrected` | rien n'est écrit | `ConfigError`, code 2 |
| Ratio invalide | `dev_ratio` ≤ 0 ou ≥ 1 | rien n'est écrit | `ConfigError("--dev-ratio", …)`, code 2 |
| Texte modifié après le Gel | `text` d'une Question changé | refus | `ConfigError` « empreinte différente » (attendue et calculée) |
| Jeu non gelé | `freeze: null` | refus | `ConfigError` « jeu non gelé » |
| Seul `contaminated_by` change | Jeu gelé puis filtré | `verify_frozen` passe | — |
| Sélection dev | `split="dev"` | seulement `validated`/`corrected` de `split == "dev"`, dans l'ordre du fichier | — |
| Sélection test | `split="test"` explicite | seulement `validated`/`corrected` de `split == "test"` | — |
| Partie inconnue | `split="tout"` | refus | `ConfigError` |

## Design Notes

L'empreinte est calculée sur le modèle Pydantic (`model_dump(mode="json")`) et non sur les octets du fichier. Ainsi, commentaires, mise en forme YAML et ordre des clés n'ont pas d'effet, alors que tout changement de contenu, `split` compris, est détecté.

```python
def fingerprint(doc: QuestionsFile) -> str:
    d = doc.model_dump(mode="json")
    d.pop("freeze", None)
    for q in d["questions"]:
        q.pop("contaminated_by", None)
    return hashlib.sha256(canonical_json(d).encode("utf-8")).hexdigest()
```

## Décisions prises sans l'utilisateur

- La fonction de gel s'appelle `freeze_questions`, plutôt que `freeze` qui aurait fait doublon avec le nom du module (`freeze.freeze`).
- Arrondi au plus proche avec les demis vers le haut (`floor(n*r + 0.5)`), plutôt que l'arrondi bancaire de `round()` ou la troncature.
- Les `rejected` reçoivent `split: null`, plutôt que de garder une valeur obsolète ou d'être réparties.
- `split` est inclus dans l'empreinte, plutôt qu'exclu, pour que la répartition elle-même soit protégée.
- Un Jeu déjà gelé peut être regelé, la répartition étant recalculée sans tenir compte de l'ancienne. L'option écartée était de refuser le regel.
- `dev_ratio` doit être strictement compris entre 0 et 1, plutôt que de tolérer 0 ou 1 qui viderait une partie.
- Un Jeu sans Question participante est refusé, plutôt que gelé vide.
- Le mélange utilise `random.Random(sha16(seed, "split", type))` directement, sans `Context` : on obtient le même tirage que `ctx.rng("split", type)` sans créer de contexte d'Exécution pour une commande qui n'en est pas une.
- `select_questions` filtre seulement et `split` vaut `"dev"` par défaut ; le runner appelle `verify_frozen` séparément. L'option écartée était que la sélection vérifie elle-même le Gel.
- `verify_frozen` prend un `QuestionsFile` plutôt qu'un chemin.
