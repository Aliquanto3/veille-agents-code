## Intent

**Problème :** `registry.py` est vide. Pour l'instant, rien ne permet d'enregistrer un Composant ou une Architecture, de le retrouver par `(kind, name)` ni de le lister. Sans registre, il faudrait câbler chaque nouveau module dans l'orchestration à la main (UJ-4, FR-2).

**Approche :** dans `wavelibrarian/registry.py`, ajouter le décorateur `@register(kind, name)`, avec `get`, `list_components` et `discover`. `discover` importe les modules par `pkgutil`. Les contrôles s'appuient sur `KINDS` de `ports.components` et lèvent `ConfigError`. Ajouter ensuite la commande `wl registre [--kind]`, qui affiche en français les entrées, leur description et leurs Params.

## Boundaries & Constraints

**Always :**
- Code, docstrings et messages en français. Les seules exceptions levées viennent de `core/errors.py` (`ConfigError(path, message)`).
- La liste fermée des `kind` est `wavelibrarian.ports.components.KINDS`. Elle est importée, jamais recopiée.
- `registry` n'importe que `ports` et `core` (contrat `layers`). `discover` importe `wavelibrarian.components` et `wavelibrarian.architectures` par `importlib.import_module` à partir de chaînes, puis parcourt récursivement leurs sous-modules par `pkgutil.walk_packages`. Une erreur d'import se propage, elle n'est jamais avalée.
- Ordre des contrôles dans `register` : `kind` hors de `KINDS`, puis `(kind, name)` déjà pris, puis `Params`. Si la classe définit `Params`, ce doit être une sous-classe de `BaseModel` avec `extra="forbid"` et `frozen=True`. Sinon : `ConfigError`. Si `Params` est absent, la classe n'a aucun paramètre.
- La description est `inspect.cleandoc(cls.__doc__)` lu sur la classe elle-même, sans héritage. Sans docstring, elle vaut `""`.
- Un nom inconnu lève une `ConfigError` dont le message liste, triés, les noms disponibles pour ce seul `kind`.
- `wl registre` appelle `discover()` avant de lister. Il sort en 0. Un `--kind` hors de la liste donne le message de la `ConfigError` sur stderr et le code 2.

**Never :**
- Ni `ctx.build`, ni construction `cls(params, ctx)`, ni validation d'Expérience (stories 1.5, 1.6, 4.x).
- Aucun Composant ni aucune Architecture concrets.
- Pas d'appel implicite à `discover()` dans `get` ou `list_components`.
- Pas de drapeau « déjà découvert » : l'idempotence repose sur le cache `sys.modules`.
- Pas de nouveau contrat import-linter. Le décompte reste « 5 kept ».

## Design Notes

Esquisse de référence :

```python
def register(kind: str, name: str) -> Callable[[type[T]], type[T]]:
    def decorer(cls: type[T]) -> type[T]:
        if kind not in KINDS:
            raise ConfigError(kind, f"kind inconnu ; admis : {', '.join(KINDS)}")
        if (kind, name) in _REGISTRE:
            raise ConfigError(f"{kind}.{name}", "déjà enregistré")
        _verifier_params(kind, name, cls)
        _REGISTRE[(kind, name)] = cls
        return cls
    return decorer
```

`walk_packages` importe lui-même les sous-paquets pour descendre dans l'arbre. Il faut lui passer `onerror` qui relance l'exception, sinon les `ImportError` sont ignorées.

## Décisions prises sans l'utilisateur

- `ConfigError.path` : `kind` pour un `kind` invalide, `kind.name` dans les autres cas. Écarté : un chemin d'Expérience, qui reste le rôle de la story 1.6.
- `Params` absent : accepté, la classe n'a aucun paramètre. Écarté : un refus, qui casserait des classes de test sans Params. `Params` présent mais non conforme : `ConfigError`. Écarté : l'accepter sans contrôle.
- Description : docstring complète de la classe, nettoyée et non héritée. Écartés : la première ligne seule, et `inspect.getdoc`, qui hérite de `ArchitectureBase`.
- Forme de la liste : `ComponentInfo` avec `params` en dict de `ParamInfo`. Écarté : des dicts bruts.
- `get` et `list_components` n'appellent pas `discover()`. Écarté : la découverte implicite.
- Idempotence de `discover` par le cache `sys.modules`. Écarté : un drapeau global, qui empêcherait de découvrir un module ajouté après le premier appel.
- Erreur d'import pendant `discover` : propagée. Écarté : l'ignorer en silence.
- `wl registre --kind` invalide : code 2 (configuration invalide, contrats §8). Écarté : code 1.
- Registre vide : message explicite et code 0. Écarté : une sortie vide.
- Tests rangés dans `tests/unit/registry/`, avec une fixture d'isolation. Écarté : partager le registre global entre tests.
