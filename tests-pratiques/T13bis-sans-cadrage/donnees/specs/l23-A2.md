## Intent

**Problème :** aucun Parser n'est enregistré pour le format `pdf`. Avec `parser: auto`, un Corpus qui contient un PDF est donc refusé (`ConfigError` « pdf_text » non encore disponible), et une Question ne peut pas citer une page.

**Approche :** ajouter le Parser `pdf_text` (pypdfium2), enregistré au `kind` `parser` avec `formats = {"pdf"}`. Il produit un Ancrage `<doc_id>#p<page>` par page (pages numérotées à partir de 1) et un Block `text` par page non vide. Un PDF illisible lève `ValueError` : `ingest` le signale déjà au journal et l'ignore.

## Boundaries & Constraints

**Toujours :** `doc_id = sha16_bytes(raw)`. L'Ancrage de chaque page est `Anchor(anchor_id=f"{doc_id}#p{n}", doc_id, source_path, page=n, heading_path=())`, déclaré dans l'ordre des pages, même si la page est vide. Une page dont le texte nettoyé n'est pas vide donne un seul Block `kind="text"` sous son Ancrage. Les fins de ligne sont normalisées en `\n` et le texte est nettoyé par `strip()`. Les ressources pdfium (pages, textpage, document) sont fermées, y compris en cas d'erreur, pour que Windows ne garde pas de verrou. La classe a `version = "1"` et une classe `Params` (forbid + frozen). Code, docstrings et messages sont en français.

**Jamais :** pas d'OCR, pas de détection de titres ou de tableaux dans un PDF, pas de docling. Ne pas utiliser `SectionBuilder`, qui est fait pour les titres. Ne pas modifier `ingest.py`, `core/types.py` ni `pyproject.toml` (pypdfium2 et fpdf2 y sont déjà). Pas de PDF binaire commité pour les tests : on les génère avec fpdf2 dans le test.

## I/O & Edge-Case Matrix

| Scénario | Entrée / État | Sortie attendue | Erreur |
|---|---|---|---|
| PDF de 3 pages | fpdf2, un texte distinct par page | 3 Blocks `text` (`#p1`, `#p2`, `#p3`), chaque texte retrouvé ; `anchors` a 3 entrées avec `page` = 1, 2, 3 | — |
| Page sans texte | page vide entre deux pages avec texte | Ancrage `#p2` présent, aucun Block pour cette page, `anchor_text` vaut `""` | aucune exception |
| PDF tronqué | `raw[: len(raw) // 2]` ou `b"%PDF-1.4 tronque"` | `parse` lève `ValueError("PDF illisible : …")` | `ingest` journalise « Document illisible ignoré », les autres Documents sont ingérés |
| `resolve` d'une page | Corpus avec `docs/registre.pdf` (3 pages) | `resolve("docs/registre.pdf", 2, ())` renvoie `<doc_id>#p2` ; page 9 renvoie `None` | — |

## Design Notes

Page vide : son Ancrage existe, mais elle ne produit aucun Block, ce qui garde la règle commune « pas de Block vide » (`_sections.py:82-84`). `anchor_text` renvoie alors `""`, ce qui correspond au « texte vide » de l'AC. Un seul Block par page : l'Ancrage est la page, et le Découpage (epic 4) se chargera de redécouper.

```python
anchors[aid] = Anchor(anchor_id=aid, doc_id=doc_id, source_path=source_path, page=n)
if texte:
    blocks.append(Block(text=texte, anchor_id=aid, kind="text"))
```

## Décisions prises sans l'utilisateur

- Une page vide a son Ancrage mais aucun Block ; l'option écartée était un Block au texte vide, qui aurait cassé l'invariant « Blocks non vides » des Parsers existants.
- Un Block `text` par page ; l'option écartée était un Block par paragraphe (`\n\n`), car l'extraction pdfium ne délimite pas les paragraphes de façon fiable.
- L'erreur pdfium est convertie en `ValueError` dans le Parser ; l'option écartée était d'élargir le `except` de `ingest.py`, ce qui aurait masqué des erreurs de programmation dans les autres Parsers.
- Les PDF de test sont générés par fpdf2 avec la police Helvetica et un texte ASCII ; l'option écartée était une police TTF commitée, réservée au Mini-corpus de la story 2.5.
- Les tests de 2.2 qui supposaient l'absence de `pdf_text` sont mis à jour ; l'option écartée était de les conserver, ce qui les aurait laissés en échec.
- `version = "1"` et un nom de registre `pdf_text` alignés sur `AUTO` ; aucune alternative crédible n'existait.
