## Intent

**Problem:** `uv run wavelocalai-v2` démarre le serveur sans jamais ouvrir de navigateur : l'utilisateur doit taper l'URL locale lui-même (retour R1 de la recette du 2026-10-21).

**Approach:** une fois le serveur prêt, le lanceur ouvre une seule fois le navigateur par défaut sur `http://127.0.0.1:<port>/`. Un fil d'arrière-plan attend que le port réponde. On coupe l'ouverture avec `--no-browser` ou `[server] open_browser = false`. Si l'ouverture échoue, l'URL part dans la console et le journal, et le serveur continue.

## Boundaries & Constraints

**Always:** le navigateur s'ouvre après qu'une connexion TCP à `127.0.0.1:<port>` a réussi, jamais avant, et une seule fois par lancement. Le fil est un démon qui ne lève jamais d'exception : quoi qu'il arrive, il ne bloque ni n'arrête le serveur. `--no-browser` l'emporte sur le `.toml`. Les tests, la CI et les E2E lancent le serveur sans navigateur. Code, messages et docstrings sont en français.

**Never:** renommer le script (c'est la story 8.4). Ajouter une variable d'environnement. Ouvrir sur `localhost` ou sur une autre route que `/`. Relancer l'ouverture après un échec. Faire un vrai appel au navigateur dans un test.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Lancement normal | `open_browser` vrai, le port finit par répondre | `webbrowser.open("http://127.0.0.1:<port>/")` est appelé une fois ; la fonction rend `True` | N/A |
| Port qui ne répond pas | rien n'écoute avant `timeout_s` | aucun appel au navigateur ; la fonction rend `False` | journal en `debug`, aucune exception |
| Aucun navigateur | `webbrowser.open` rend `False` | `warning` avec l'URL (console et journal) ; rend `False` | le serveur continue |
| Session sans affichage | `webbrowser.open` lève `webbrowser.Error` ou `OSError` | même `warning` avec l'URL ; rend `False` | l'exception est absorbée |
| Désactivé | `--no-browser` ou `[server] open_browser = false` | aucun fil lancé, aucun appel | N/A |

**Interface imposée :** `wavelocalai.__main__._open_browser_when_ready(port: int, *, timeout_s: float = 30.0, poll_s: float = 0.1) -> bool`. La fonction est bloquante. Elle essaie `socket.create_connection(("127.0.0.1", port), timeout=poll_s)` jusqu'au délai. Dès qu'une connexion réussit, elle la ferme et appelle `webbrowser.open(url)`, une seule fois. Elle rend `True` seulement si le navigateur a été ouvert. `import webbrowser` se fait en tête du module, et l'appel passe par l'attribut du module (`webbrowser.open`), pour que les tests puissent le remplacer.

**Acceptance Criteria:**
- Given `uv run wavelocalai-v2` avec les réglages par défaut, when uvicorn écoute, then le navigateur par défaut s'ouvre une seule fois sur `http://127.0.0.1:<port>/`.
- Given un lancement refusé (port occupé, dossier verrouillé, base trop récente), when `main` rend 1, then aucun navigateur ne s'ouvre.
- Given un `.toml` qui contient `[server] open_browser = false` et un port surchargé par `--port`, when les réglages sont chargés, then les deux réglages sont appliqués (aucune surcharge n'écrase l'autre).
- Given la suite de tests et les E2E, when ils lancent `python -m wavelocalai`, then la commande porte `--no-browser`.

## Design Notes

La boucle de connexion (l'attente) est séparée de l'ouverture. On peut ainsi tester la fonction de façon synchrone, sans fil ni serveur. Le fil est un démon : quand uvicorn s'arrête ou que le lancement échoue, le fil meurt avec le processus, sans `join`. Le log `info` existant (« wavelocalai-v2 sur http://127.0.0.1:… ») reste l'endroit habituel de l'URL. Le `warning` ne s'ajoute qu'en cas d'échec.

## Décisions prises sans l'utilisateur

- Signature `_open_browser_when_ready(port, *, timeout_s=30.0, poll_s=0.1) -> bool`, bloquante, appelée dans un fil démon par `main`. Écarté : une fonction qui lance elle-même le fil (plus difficile à tester).
- Le moment où « le port répond » est la première connexion TCP réussie à `127.0.0.1:<port>`. Écarté : interroger `GET /api/health`, qui ajoute une dépendance HTTP et des en-têtes Host.
- Le message d'échec est un seul `logger.warning`, qui atteint la console (stderr) et le journal par les handlers existants. Écarté : un `print` en plus, qui doublerait le message à la console.
- Un délai dépassé, faute de serveur prêt, ne donne qu'un log `debug`, sans navigateur. Écarté : un `warning`, qui ferait doublon avec l'erreur de démarrage.
- Les lancements en test passent `--no-browser` de façon explicite. Écarté : couper le navigateur dès que `WAVELOCALAI_TESTING` est actif (ce couplage n'est demandé nulle part).
- Aucune variable d'environnement `WAVELOCALAI_OPEN_BROWSER`. Écarté : l'ajouter à `ENV_OVERRIDES` (hors du périmètre de la story).
- `wavelocalai.toml` et `README.md` documentent le réglage. Écarté : laisser le réglage sans documentation.
