## Intent

**Problem:** Le Rapport (stories 4.11 à 4.13) a besoin d'intervalles de confiance, de comparaisons appariées et de fronts de Pareto. Ces calculs doivent être reproductibles et conformes à scipy (FR-39, FR-40). Aujourd'hui, `stats/` ne contient que `kappa.py`.

**Approach:** Ajouter trois modules de fonctions pures (AD-22) dans `wavelibrarian.stats` : `bootstrap.py`, `mcnemar.py` et `pareto.py`. Chacun est déterministe pour une graine donnée (AD-20) et vérifié contre scipy dans des tests unitaires.

## Boundaries & Constraints

**Always:**
- Les valeurs par défaut sont 2 000 rééchantillons et un niveau de 95 %. Le générateur est `numpy.random.default_rng(seed)`, construit à partir de l'entier `seed` reçu. Dériver la graine de l'Expérience revient à l'appelant (le report).
- Les comparaisons utilisent uniquement les `question_id` communs, triés par ordre croissant avant le rééchantillonnage, et renvoient `n_common`.
- Il n'y a aucun I/O, aucun état global et aucun import de couches hautes : seuls `numpy`, `scipy` et la bibliothèque standard sont autorisés (contrat import-linter, `stats` est au niveau de `llm`/`measure`).
- Le code, les docstrings et les messages d'erreur sont en français, dans le style de `stats/kappa.py`.

**Never:**
- Pas d'agrégation par (config_id, condition, tier, phase), pas d'écriture de CSV ou de `report.md`, pas d'export du front : tout cela relève des stories 4.11 à 4.13.
- Pas de pondération entre Critères ni de score global.
- Pas de `numpy.random` global (`np.random.seed`, etc.).

**Interface imposée** (les tests d'acceptation l'importent) :
- `wavelibrarian.stats.bootstrap` :
  - `IntervalleConfiance(NamedTuple)` : `low: float`, `high: float`. Il se déballe en `(low, high)`, comme le `ConfidenceInterval` de scipy.
  - `bootstrap_ci(values: Sequence[float], n_resamples: int = 2000, confidence_level: float = 0.95, seed: int = 0) -> IntervalleConfiance` : IC par percentile de la moyenne. Délègue à `scipy.stats.bootstrap(..., method="percentile", rng=np.random.default_rng(seed))`.
  - `ComparaisonContinue` (dataclass figée) : `diff`, `ci_low`, `ci_high`, `p_value` (`float | None`), `n_common: int`.
  - `paired_bootstrap(a, b, n_resamples=2000, confidence_level=0.95, seed=0) -> ComparaisonContinue` : travaille sur `d = a - b`. `diff = mean(d)`. L'IC est celui de `bootstrap_ci` sur `d`. Le calcul de la p-valeur est décrit dans Design Notes.
  - `compare_continu(a: Mapping[str, float], b: Mapping[str, float], **mêmes options) -> ComparaisonContinue` : prend les ids communs triés, puis appelle `paired_bootstrap`. Si aucun id n'est commun, renvoie des champs à `None` avec `n_common=0`.
- `wavelibrarian.stats.mcnemar` :
  - `mcnemar_exact(b: int, c: int) -> float` : `scipy.stats.binomtest(c, b + c, 0.5).pvalue` (bilatéral). Renvoie `1.0` si `b + c == 0`.
  - `ComparaisonBinaire` (dataclass figée) : `diff` (taux de oui de A moins celui de B sur les communes), `b` (A oui, B non), `c` (A non, B oui), `p_value` (`float | None`), `n_common`.
  - `compare(a: Mapping[str, bool], b: Mapping[str, bool]) -> ComparaisonBinaire` : intersection des clés. Si `n_common=0`, `diff` et `p_value` valent `None`.
- `wavelibrarian.stats.pareto` :
  - `Point` (dataclass figée) : `config_id: str`, `qualite: float` (à maximiser), `cout: float` (à minimiser : coût, énergie ou latence p95).
  - `front_pareto(points: Sequence[Point]) -> list[Point]`.

## Design Notes

P-valeur bilatérale du bootstrap apparié, calculée sur la distribution `dist = res.bootstrap_distribution` des moyennes rééchantillonnées de `d` :

```python
p = min(1.0, 2.0 * min(np.mean(dist <= 0.0), np.mean(dist >= 0.0)))
```

Pour n = 1, `dist` est constante, égale à `d[0]`. La même formule donne alors 0 si `d[0] != 0` et 1 sinon, ce qui reste cohérent avec le cas général.

Pour `statistic`, utiliser `np.mean` avec `axis=-1` (la forme vectorisée détectée par scipy), afin que le tirage d'indices soit celui de la référence scipy.

## Décisions prises sans l'utilisateur

- IC calculé par délégation à `scipy.stats.bootstrap(method="percentile")` ; option écartée : réimplémentation numpy du tirage, fragile face aux évolutions internes de scipy.
- Type de retour de `bootstrap_ci` = `NamedTuple(low, high)` ; options écartées : un tuple nu, ou un objet sans déballage.
- Noms des paramètres : `n_resamples`, `confidence_level` (comme scipy) et `seed: int` ; option écartée : passer un `Generator` en paramètre.
- Graine utilisée telle quelle (`default_rng(seed)`), sa dérivation `sha16` restant à la charge du report ; option écartée : dériver la graine dans `stats`.
- P-valeur appariée par la règle des percentiles bilatéraux sur la distribution bootstrap ; option écartée : test par permutation de signes.
- `mcnemar_exact` utilise `binomtest(c, b + c)` sans correction et vaut 1 si b = c = 0 ; option écartée : McNemar asymptotique (chi²).
- Aucune Question commune : statistiques à `None` et `n_common=0` ; options écartées : une exception, ou NaN.
- Vecteur vide dans `bootstrap_ci` : `ValueError` ; vecteur d'un seul élément : IC `(v, v)` ; option écartée : laisser remonter l'erreur de scipy.
- `Point(config_id, qualite, cout)` générique, réutilisé pour les fronts énergie et latence ; option écartée : un type par front ou des champs `x`/`y`.
- Points à égalité exacte : tous deux conservés comme non dominés ; option écartée : n'en garder qu'un.
- Ordre du front : coût ↑, puis Qualité ↓, puis `config_id` ↑ ; option écartée : un tri par Qualité d'abord.
