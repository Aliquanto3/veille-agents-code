J'ai passé deux jours à vérifier ce que valent vraiment les outils censés rendre les agents de code moins chers ou meilleurs : 15 tests pratiques, sur mes propres projets et sur 45 jours de transcriptions Claude Code.

Résultat : aucun dépôt de ma liste de veille ne fait strictement mieux que l'option la plus simple.

Ce qui rapporte, mesures à l'appui :
• Réduire le contexte fixe. 8 outils rarement appelés pesaient 17,8 k tokens à chaque appel.
• Demander un second avis à Haiku avant la revue. 87 % de ses constats sérieux ont été corrigés, pour 0,03 $ par story.
• Implémenter avec Sonnet seul : 0,53 $ par story, contre 1,33 $ avec Opus, pour le même taux de réussite.
• Vérifier les critères d'acceptation dans un vrai navigateur. Dans mes tests de design, c'est le seul contrôle qui a relevé un écart.

Ce qui ne rapporte pas, mesuré aussi :
• un relecteur d'une autre famille de modèles (+6 points, non significatif) ;
• le verrouillage des tests (aucune triche sur 40 runs) ;
• /advisor ;
• les tests property-based ;
• les juges de commandes shell ;
• la compression des sorties ;
• les modèles locaux au quotidien ;
• raccourcir un CLAUDE.md de quelques milliers de tokens.

Le résultat qui m'a le plus surpris vient de la mutation guidée. On lance des mutations sur le code de la story, puis on montre à l'agent les mutants qui survivent à ses tests. L'agent a bouché les 134 trous non équivalents, sans exception. Avec la simple consigne « renforce tes tests », il n'en bouchait que 59 %. Il a aussi reconnu sans erreur les 35 mutants équivalents. Le coût est de 0,22 $ par story. C'est le seul ajout à ma chaîne que les tests justifient, et je l'ajoute comme étape optionnelle de la revue.

Avant d'ajouter un outil, mesurez-le sur vos propres données. Chez moi, les gains sont venus plus souvent de ce que j'ai retiré que de ce que j'ai ajouté.
