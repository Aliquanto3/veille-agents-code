J'ai passé deux jours à vérifier ce que valent vraiment les outils censés rendre les agents de code moins chers ou meilleurs. J'ai fait 15 tests pratiques, sur mes propres projets et sur 45 jours de transcriptions Claude Code. Résultat : aucun dépôt de ma liste de veille ne fait strictement mieux que l'option la plus simple.

Ce qui rapporte, chiffres à l'appui :
• Réduire le contexte fixe. Huit outils rarement appelés pesaient 17,8 k tokens à chaque appel.
• Demander un second avis à Haiku avant la revue. 87 % de ses constats sérieux ont été corrigés, pour 0,03 $ par story.
• Implémenter avec Sonnet seul. Il coûte 0,53 $ par story contre 1,33 $ pour Opus, et réussit aussi souvent.
• Vérifier les critères d'acceptation dans un vrai navigateur. Sur mes tests de design, aucun autre contrôle n'a relevé d'écart.

Ce qui ne rapporte pas, mesuré aussi :
• un relecteur d'une autre famille de modèles (+6 points, non significatif) ;
• verrouiller les tests (aucune triche sur 40 runs) ;
• /advisor ;
• les tests property-based ;
• les juges de commandes shell ;
• la compression des sorties ;
• les modèles locaux au quotidien ;
• tailler un CLAUDE.md de quelques milliers de tokens.

Ma principale découverte est la mutation guidée. On lance une mutation sur le code de la story, puis on montre à l'agent les mutants qui survivent à ses tests. Il a alors bouché les 134 trous non équivalents, sans exception. Avec une simple consigne « renforce tes tests », il n'en bouchait que 59 %. Il a aussi reconnu sans erreur les 35 mutants équivalents, pour un coût de 0,22 $ par story. Parmi tout ce que j'ai testé, c'est le seul ajout à ma chaîne que les résultats justifient. Je le garde comme étape optionnelle de la revue.

Ce que j'en retiens : avant d'ajouter un outil, mesurez-le sur vos propres données. Les gains viennent plus souvent de ce qu'on retire que de ce qu'on ajoute.
