J'ai passé deux jours à vérifier ce que valent vraiment les outils censés rendre les agents de code moins chers ou meilleurs. J'ai fait 15 tests pratiques, sur mes propres projets et sur 45 jours de transcriptions Claude Code.

Aucun des dépôts de ma liste de veille ne fait strictement mieux que l'option la plus simple.

Ce qui rapporte, d'après mes mesures :
• Alléger le contexte fixe : 8 outils rarement utilisés ajoutaient 17,8 k tokens à chaque appel.
• Demander un second avis à Haiku avant la revue : 87 % de ses constats sérieux ont été corrigés, pour 0,03 $ par story.
• Confier l'implémentation à Sonnet seul : il réussit aussi souvent qu'Opus, pour 0,53 $ par story au lieu de 1,33 $.
• Vérifier les critères d'acceptation dans un vrai navigateur. Sur mes tests de design, c'est le seul contrôle à avoir repéré un écart.

Ce qui ne rapporte pas, mesuré de la même façon :
• faire relire par un modèle d'une autre famille (+6 points, non significatif) ;
• verrouiller les tests (aucune triche sur 40 runs) ;
• /advisor ;
• les tests property-based ;
• les juges de commandes shell ;
• la compression des sorties ;
• les modèles locaux au quotidien ;
• raccourcir un CLAUDE.md de quelques milliers de tokens.

Mon principal résultat concerne la mutation guidée. On lance des tests de mutation sur le code de la story, puis on montre à l'agent les mutants qui ont survécu à ses tests. Il a comblé 134 trous non équivalents sur 134, alors qu'il n'en comblait que 59 % quand on lui demandait simplement de « renforcer ses tests ». Il a aussi reconnu sans erreur les 35 mutants équivalents. Coût : 0,22 $ par story. De tout ce que j'ai testé, c'est le seul ajout à ma chaîne que les tests justifient, comme étape optionnelle de la revue.

Avant d'ajouter un outil, mesurez-le sur vos propres données. Le plus souvent, on gagne davantage à retirer qu'à ajouter.
