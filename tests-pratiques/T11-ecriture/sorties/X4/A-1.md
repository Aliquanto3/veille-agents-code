Observation 8. Skills have overtaken MCP as the most widely adopted extensibility standard in the corpus. Nine of the 11 systems implement SKILL.md bundles (only Aider and Mini-SWE-Agent do not), against 8 of 11 for MCP. The two were tied in April; Pi broke the tie by explicitly supporting skills but not MCP. Three further developments show this layer maturing. First, deferred loading is now close to universal: 8 of the 9 adopters use it. Second, conditional activation (Claude Code's `paths`, OpenHands's PathTrigger, OpenClaw's `requires`) brings just-in-time (JIT) context engineering into the extensibility layer. Third, a supply chain has appeared. Four systems have hosted registries, Hermes has trust tiers and quarantine, and OpenClaw verifies provenance. The first agent-authored skills have also appeared: Hermes's self-improving loop and Gemini CLI's extraction inbox.

Deferred loading is the dominant pattern. This follows Claude Code's deferred tool loading (Section 8.3). Eight of the nine adopters now load only skill metadata up front and fetch a skill's body when it is needed. They do this in different ways:
- a dedicated tool (SkillTool, ActivateSkill, `skill`, OpenHands's `invoke_skill`);
- `$`-mentions plus detection of implicit invocation (Codex);
- a three-tier disclosure chain (Hermes);
- most minimally, the ordinary read tool used against an XML index (Pi).

In April, OpenHands still loaded skills eagerly; it moved to progressive disclosure with the V1 SDK. OpenClaw is now the only eager loader. It makes up for this with eligibility gating, so skills that don't qualify never reach the prompt.

Gating and conditional activation. The most architecturally interesting difference between systems is conditional activation. OpenClaw skills declare runtime requirements (binaries on PATH, environment variables, OS family), and the system filters them at load time. As a result, a "how to use kubectl" skill doesn't clutter the prompt on a machine that doesn't have kubectl. In Claude Code, the `paths` frontmatter activates a skill when the model touches matching files through the Read, Edit, or Write tools. OpenHands now does the same thing with PathTrigger rules that are injected when a file is touched. Both approaches tie skills to the JIT context philosophy of [19]. This is a structural advance over MCP, which treats every connected server the same way, whether or not its tools are relevant to the current task.
