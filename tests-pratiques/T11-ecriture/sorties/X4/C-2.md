Observation 8. Skills have overtaken MCP as the most widely adopted extensibility standard in the corpus. Nine of the 11 systems implement SKILL.md bundles (only Aider and Mini-SWE-Agent do not), against 8 of 11 for MCP. The two were tied in April. Pi broke the tie by explicitly supporting skills but not MCP. Three second-order developments show that this layer is maturing. First, deferred loading is now the near-universal strategy (8 of the 9 adopters). Second, conditional activation (Claude Code's paths, OpenHands's PathTrigger, OpenClaw's requires) brings just-in-time (JIT) context engineering into the extensibility layer. Third, a supply chain has emerged: hosted registries in four systems, trust tiers and quarantine in Hermes, and provenance verification in OpenClaw. The first agent-authored skills have appeared alongside it (Hermes's self-improving loop, Gemini CLI's extraction inbox).

Deferred loading as the dominant pattern. Eight of the nine adopters now load only skill metadata up front and fetch the full body when it is needed, echoing Claude Code's deferred tool loading (Section 8.3). They fetch it in different ways:
- through a dedicated tool (SkillTool, ActivateSkill, skill, OpenHands's invoke_skill);
- through $-mentions and implicit-invocation detection (Codex);
- through a three-tier disclosure chain (Hermes);
- or, most minimally, through the ordinary read tool pointed at an XML index (Pi).

OpenHands loaded skills eagerly in April but switched to progressive disclosure with the V1 SDK. OpenClaw is now the only eager loader. It compensates with eligibility gating, so ineligible skills never reach the prompt.

Gating and conditional activation. Conditional activation is the most architecturally interesting variation. OpenClaw skills declare runtime requirements (binaries on PATH, environment variables, OS family) and are filtered at load time. This keeps "how to use kubectl" out of the prompt on a machine that doesn't have kubectl. Claude Code's paths frontmatter activates a skill when the model touches matching files through the Read, Edit, or Write tools. OpenHands now implements the same idea as PathTrigger rules, which are injected when a file is touched. Both approaches tie skills to the JIT context philosophy of [19]. This is a structural advance over MCP, which treats every connected server the same way, whether or not its tools are relevant to the current task.
