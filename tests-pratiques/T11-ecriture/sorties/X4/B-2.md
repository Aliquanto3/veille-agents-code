Observation 8. Skills are now the corpus's most widely adopted extensibility standard, ahead of MCP. Nine of the 11 systems implement SKILL.md bundles (only Aider and Mini-SWE-Agent do not), compared with 8 of 11 for MCP. The two were tied in April, and Pi broke the tie with its explicit position of supporting skills but not MCP. Three second-order developments show the layer maturing. Deferred loading is now the near-universal strategy, used by 8 of the 9 adopters. Conditional activation (Claude Code's paths, OpenHands's PathTrigger, OpenClaw's requires) brings just-in-time (JIT) context engineering into the extensibility layer. A supply chain has also emerged, with hosted registries in four systems, trust tiers and quarantine in Hermes, and provenance verification in OpenClaw. The first agent-authored skills have appeared alongside it, in Hermes's self-improving loop and Gemini CLI's extraction inbox.

Deferred loading as the dominant pattern. Like Claude Code's deferred tool loading (Section 8.3), eight of the nine adopters now load only skill metadata up front and fetch skill bodies on demand. Some use a dedicated tool (SkillTool, ActivateSkill, skill, or OpenHands's invoke_skill). Codex uses $-mentions and implicit-invocation detection, and Hermes uses a three-tier disclosure chain. Pi has the most minimal approach: the ordinary read tool, pointed at an XML index. OpenHands loaded skills eagerly in April and moved to progressive disclosure with the V1 SDK. OpenClaw is now the only eager loader. It makes up for this with eligibility gating, so ineligible skills never reach the prompt.

Gating and conditional activation. Architecturally, the most interesting variation is conditional activation. OpenClaw's skills declare runtime requirements (binaries on PATH, environment variables, OS family) and are filtered at load time. On a machine without kubectl, for example, a "how to use kubectl" skill never ends up in the prompt. Claude Code's paths frontmatter activates a skill when the model touches matching files through the Read, Edit, or Write tools. OpenHands now implements the same idea as PathTrigger rules, which are injected when a file is touched, tying skills to the JIT context philosophy of [19]. This is a structural advance over MCP, which treats every connected server the same way whether or not its tools are relevant to the current task.
