Observation 8. Skills have overtaken MCP as the most widely adopted extensibility standard in the corpus. Nine of the 11 systems implement SKILL.md bundles (all except Aider and Mini-SWE-Agent), while 8 of 11 implement MCP. The two were tied in April, and Pi broke the tie by supporting skills explicitly but not MCP. Three second-order developments show that this layer is maturing. Deferred loading is now the near-universal strategy (8 of the 9 adopters). Conditional activation (Claude Code's paths, OpenHands's PathTrigger, OpenClaw's requires) brings just-in-time (JIT) context engineering into the extensibility layer. A supply chain has also emerged: four systems have hosted registries, Hermes has trust tiers and quarantine, and OpenClaw verifies provenance. The first skills written by agents have appeared alongside it (Hermes's self-improving loop, Gemini CLI's extraction inbox).

Deferred loading as the dominant pattern. Eight of the nine adopters now work the same way as Claude Code's deferred tool loading (Section 8.3). They load only the skill metadata up front and fetch the full body when it is needed. The systems fetch it in different ways:
- a dedicated tool (SkillTool, ActivateSkill, skill, OpenHands's invoke_skill);
- $-mentions and detection of implicit invocation (Codex);
- a three-tier disclosure chain (Hermes);
- at the most minimal, the ordinary read tool pointed at an XML index (Pi).

OpenHands loaded skills eagerly in April and moved to progressive disclosure with the V1 SDK. That leaves OpenClaw as the only eager loader. It compensates with eligibility gating, so ineligible skills never reach the prompt.

Gating and conditional activation. Conditional activation is the most architecturally interesting variation. OpenClaw skills declare runtime requirements (binaries on PATH, environment variables, OS family) and are filtered at load time, so "how to use kubectl" does not pollute the prompt on a machine that has no kubectl. In Claude Code, the paths frontmatter activates a skill when the model touches matching files through the Read, Edit, or Write tools. OpenHands now implements the same idea as PathTrigger rules, which are injected when a file is touched. This connects skills to the JIT context philosophy of [19]. It is also a structural advance over MCP, which treats every connected server the same way whether or not its tools are relevant to the current task.
