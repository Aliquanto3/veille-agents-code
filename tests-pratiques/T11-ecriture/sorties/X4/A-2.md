Observation 8. Skills have overtaken MCP as the most widely adopted extensibility standard in the corpus. Nine of the 11 systems implement SKILL.md bundles; only Aider and Mini-SWE-Agent do not. MCP is at 8 of 11. The two were tied in April, and Pi broke the tie by explicitly supporting skills but not MCP. Three second-order developments show the layer maturing:

- **Deferred loading** is now close to universal, used by 8 of the 9 adopters.
- **Conditional activation** brings JIT context engineering into the extensibility layer. Examples are Claude Code's `paths`, OpenHands's PathTrigger and OpenClaw's `requires`.
- **A supply chain** has emerged. Four systems have hosted registries, Hermes has trust tiers and quarantine, and OpenClaw verifies provenance. The first agent-authored skills have also appeared: Hermes's self-improving loop and Gemini CLI's extraction inbox.

Deferred loading as the dominant pattern. This follows the same approach as Claude Code's deferred tool loading (Section 8.3). Eight of the nine adopters now load only skill metadata up front and fetch the full skill body when it is needed. They do this in different ways:

- through a dedicated tool (SkillTool, ActivateSkill, `skill`, OpenHands's `invoke_skill`);
- through `$`-mentions and implicit-invocation detection (Codex);
- through a three-tier disclosure chain (Hermes);
- or, most minimally, through the ordinary read tool pointed at an XML index (Pi).

OpenHands loaded everything up front in April, which made it the outlier. With the V1 SDK it moved to progressive disclosure. OpenClaw is now the only system that loads skills up front. It makes up for this with eligibility gating, so skills that don't qualify never reach the prompt.

Gating and conditional activation. Architecturally, the most interesting difference between systems is conditional activation. In OpenClaw, each skill declares what it needs at runtime: binaries on PATH, environment variables, or an OS family. Skills are filtered at load time, so instructions on "how to use kubectl" don't fill the prompt on a machine that doesn't have kubectl. In Claude Code, the `paths` frontmatter activates a skill when the model touches matching files through the Read, Edit or Write tools. OpenHands now does the same thing with PathTrigger rules, which are injected when a matching file is touched. Both approaches tie skills to the JIT context philosophy of [19]. This is a structural advance over MCP, which treats every connected server the same way whether or not its tools are relevant to the current task.
