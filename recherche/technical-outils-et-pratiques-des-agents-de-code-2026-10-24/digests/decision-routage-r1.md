# Dimension `decision-routage` : modèles de décision et routeurs appris autour des agents de code (tour 1)

Chercheur : sous-agent Opus 5.5, 2026-10-24. Budget consommé : 25 appels web sur 25 et 7 lectures de dépôt sur 20. Arrêt : budget web épuisé. Les questions sont couvertes, sauf Martian, Not Diamond (le service), la politique de données de TypeSafe et un banc indépendant à 700 items (page en 403).

## 1. Résumé

- **Jev** (TypeSafe, lancé le 2026-09-15 en accès anticipé) est un **modèle de décision fermé**. Il ne génère pas de texte : il répond à des questions typées (`choice`, `score`, `noul`) sur un état et renvoie des probabilités [J1][J2][J3]. On l'appelle par l'API `POST /v1/systemone`. Selon des sources secondaires, il passe aussi par Vercel et Netlify. Sur OpenRouter, le catalogue n'expose que `typesafe/jev-router` : un routeur qui choisit **le modèle et l'effort** pour chaque requête, à prix variable [J4][J5]. Prix annoncé : 0,042 $/Mtok en entrée, sortie gratuite [J6][J7].
- **Ollama 0.35 (2026-09-29)** prend en charge les « modèles de décision » par `/v1/systemone`. Trois modèles sont disponibles : `nimble` 9B (Bespoke Labs), `tev1` 4B et `tev1:0.8b` (Together AI). **Jev n'est pas dans Ollama** [O1]. Nimble atteint 90,1 % contre 93,2 % pour Jev, mais sur le jeu de Bespoke [O3].
- Il n'existe **aucune évaluation indépendante solide de Jev**. Il y a la critique de The Register (« fast, cheap, but is it good? ») [J7] et une sonde de 70 prompts synthétiques publiée par un plugin Claude Code : Jev y obtient 70/70 avec un p95 de 299 ms, un Ollama 9B générique 66/70 avec un p95 de 3,5 s [R2].
- Le **« piège du routage » est confirmé dans son mécanisme**. Dans Claude Code, chaque modèle a son propre cache, donc changer de modèle relit tout l'historique sans cache [N3]. Le chiffrage du PDF est en revanche biaisé. Recalculé aux prix 5.5 avec la lecture du cache, le basculement du fil principal vers un modèle moins cher reste perdant sur une courte sous-tâche et devient rentable vers 25 requêtes. Un **sous-agent à contexte propre est moins cher dès le départ**, ce qui est déjà le modèle natif de Claude Code (§3.2).
- La seule étude trouvée sur le routage par étape d'un agent de code (TwinRouterBench, préprint) intègre le cache. Elle mesure une baisse de coût de 53 % à taux de résolution égal avec un routeur entraîné. Sur la piste statique de SWE-bench, en revanche, tous les routeurs ont un gain négatif : une étape sous-routée fait échouer toute la trajectoire [L1].
- **En natif** : l'auto mode est un classifieur de permissions, disponible pour tous depuis 2026-07-10 [N1]. Le `/advisor` reprend le schéma « modèle bon marché, conseiller fort ». Il **relit tout le transcript sans cache à chaque appel**, ce qui reproduit le piège en miniature [N2]. Changer d'effort garde le cache sur les modèles 5.5 [N3] : c'est le levier de routage le moins cher.
- Verdicts : décision locale par Ollama `Essayer` ; Jev en API `Évaluer` ; `claude-router` `Évaluer` ; routeurs passerelle (OpenRouter Auto ou Pareto, jev-router, Plano) `Écarter` pour Claude Code.

## 2. Fiches outils

### 2.1 Jev (TypeSafe), API directe
- **Ce que c'est** : un service de décision. L'état (texte ou JSON) et des questions typées (`choice` jusqu'à 255 options selon un tiers, `score` sur un barème, `noul` de 0 à 1) entrent dans un même appel. Les questions sont évaluées « in parallel and in isolation against the same state » [J2]. La sortie contient `choice`, `probabilities` et `confidence` [J2][O1]. La doc officielle le dit sans ambiguïté : **Jev ne remplace pas le LLM d'un agent de code**. On l'appelle depuis son propre code pour décider [J3]. TypeSafe fournit une « agent skill » pour Claude Code et Codex, qui aide seulement à écrire du code utilisant l'API [J3]. Les patterns documentés sont le routage gardé par la confiance, le routage d'intention et des garde-fous LLM qui renvoient pass, review, block ou route [J2b].
- **Accès** : `POST https://api.typesafe.ai/v1/systemone` avec une clé Bearer, modèle `jev-latest` (résolu en `jev-1.13.0`). Le fait vient de guides tiers [J8]. Les inscriptions ont été suspendues le 2026-09-22 selon un tiers (confiance basse) [J8]. Les SDK Python (`typesafe-sdk`) et JS existent [J2b][O1]. Par ailleurs : Vercel AI Gateway (`typesafe-ai/jev`, `experimental_evaluate`), Netlify AI Gateway et AI/ML API, tous d'après des sources secondaires [J8]. Cloudflare Workers AI n'est cité que par Linas et n'a pas été vérifié [J6].
- **Prix** : 0,042 $/Mtok en entrée, sortie gratuite [J6][J7]. Pas de page de prix officielle trouvée.
- **Poids** : fermés. Le dépôt Nimble l'écrit : « Jev is not open » [O3].
- **Preuves d'efficacité** : chiffres du vendeur, entre 70 et 500 ms par décision, non validés [J1]. Sur 324 exemples retenus par Bespoke, Jev obtient 93,21 % d'accord avec les étiquettes de référence [O3]. Sur la sonde d'activité de `claude-router` (70 prompts synthétiques) : 70/70, p50 de 260 ms, p95 de 299 ms [R2]. The Register parle de peu de benchmarks et d'une précision difficile à juger, et rapporte que Jev a perdu aux échecs contre GLM 5.3 [J7]. Côté calibration, Linas écrit que les probabilités ne sont « not calibrated across every new task » [J6]. TypeSafe publie lui-même une page sur les défauts connus de Jev 1.13 (« Jev isn't perfect ») [J2b].
- **Exemples liés au code** : Linas rapporte un cas où Jev, dans un run Codex, montait ou baissait l'effort de raisonnement selon que l'agent semblait bloqué, sans casser le cache. Le chiffre de 50 % d'économie est auto-déclaré [J6].
- **Maturité** : TypeSafe a levé 40 M$ en seed et lancé le 2026-09-15 [J1]. Le service a connu une saturation après le lancement, selon une seule source secondaire [J1].
- **Risques** : le texte du prompt part chez typesafe.ai à chaque décision [R1]. Je n'ai trouvé **aucune politique de rétention publiée** : la page Legal existe mais n'a pas été lue. Accès anticipé avec inscriptions suspendues. Verrouillage modéré, car le format `/v1/systemone` est repris par Ollama, ce qui offre une sortie locale.
- **Compatibilité** : appel HTTP, donc OS indifférent. Utilisable depuis un hook Claude Code ou un script.
- **Équivalent natif** : aucun comme service. L'auto mode couvre le cas « autoriser cette commande ? » [N1].
- **Verdict** : `Évaluer`. Intéressant pour des expériences hors code client. Pas sur du code client tant que la politique de données n'est pas lue et que l'accès n'est pas ouvert.

### 2.2 `typesafe/jev-router` (OpenRouter)
- **Ce que c'est** : un modèle du catalogue OpenRouter créé le 2026-09-25, décrit ainsi : « picks the best model and reasoning effort for each request, balancing quality, speed, and cost. It runs on Jev ». Le prix est variable (`-1`) [J4]. On l'appelle par Chat Completions. Il n'est pas disponible en routage régional UE [J5]. La page `jev-1.13` d'OpenRouter, citée par un moteur de recherche, renvoie aujourd'hui une 404 [J4].
- **Risques** : pour Claude Code, il faut passer par une passerelle. L'advisor exige l'API Anthropic [N2]. Le cache dépend de la façon dont la passerelle traite `cache_control` [N3]. Un changement de modèle à chaque requête repart sans cache [N3]. Les données transitent par OpenRouter, TypeSafe et le fournisseur final.
- **Verdict** : `Écarter` pour Claude Code. `Hors périmètre` pour le reste.

### 2.3 Modèles de décision dans Ollama (nimble, tev1)
- **Ce que c'est** : Ollama 0.35 (2026-09-29) ajoute `/v1/systemone`. Le format de requête est `model`, `state` et `questions` avec un `type` parmi `choice`, `noul` et `score`. La réponse donne `answers` avec probabilités et confiance, ainsi que `usage` [O1]. Le SDK `typesafe-sdk` fonctionne contre Ollama via `TYPESAFE_BASE_URL` [O1]. Les modèles : `nimble` (9B, Bespoke Labs, adaptateur LoRA sur Qwen3.5-9B [O3]), `tev1` (4B, expérimental, Together AI) et `tev1:0.8b` (0,8B, expérimental) [O1]. Des modèles servis par le cloud d'Ollama sont annoncés [O1].
- **Preuves** : 91 ms par décision pour Nimble 9B sur un M5 Max, chiffre de l'éditeur [O1]. Le blog cite une moyenne sur 13 jeux de données publics étiquetés (3 880 décisions), sans valeurs lisibles dans le texte [O1]. Bespoke donne 90,12 % pour Nimble 9B, contre 93,21 % pour Jev et 66,36 % pour Qwen3.5-9B non affiné, sur son propre jeu de 324 exemples [O3]. Bespoke cite aussi l'index tiers « Decision Index », sur lequel Nimble-v4 obtiendrait 63,70 contre 57,96 pour Jev 1.13 [O3]. Le chiffre est auto-rapporté par Bespoke et contredit un graphique antérieur du même README (Jev 60,1 contre Nimble v3 54,7). Confiance basse. Aucune mesure sur CPU ni sous Windows.
- **Maturité** : `bespokelabsai/nimble` a été créé le 2026-09-18, compte 2 249 étoiles, push le 2026-10-24. **Licence non déclarée dans l'API GitHub**, alors que Latenode annonce Apache 2.0 [O3][O4]. C'est à vérifier.
- **Risques** : rien ne sort du poste, ce qui est le principal avantage. `tev1` est expérimental. Le README de Nimble prévient qu'une confiance de 0,9 ne veut pas dire 90 % de réponses justes sur ses propres données [O3].
- **Compatibilité** : Ollama tourne sous Windows. Le blog ne dit rien de `/v1/systemone` sous Windows. `tev1:0.8b` et `tev1` entrent dans un CPU 16 Go. Nimble 9B en dépend selon la quantification : un tiers parle d'environ 18 Go pour le modèle de base non quantifié [O4].
- **Verdict** : `Essayer`. C'est le seul moyen de tester une couche de décision **sans envoyer de données à un tiers**, et cela sert directement l'objectif de comparaison local / cloud.

### 2.4 `alexei-led/claude-router` (plugin, « Mod » Claude Code)
- **Ce que c'est** : un plugin qui choisit **le modèle et l'effort pour chaque tour** du fil principal, et un modèle pour chaque sous-agent au lancement. Il s'appuie sur un classifieur au choix : Jev par défaut, Cloudflare Clef, OpenAI (`gpt-6-luna`, Decisions API) ou un modèle Ollama local [R1]. Il réinterroge le classifieur toutes les 4 requêtes. Il applique des règles locales de vote, de contexte, d'échec et de **coût du cache** avant de changer de modèle. Un passage vers un route moins chère attend un délai et un test, un build ou un lint réussi [R1]. Échelle par défaut : Haiku 5.5 pour micro et low, Opus 5.5 pour medium et high, avec Sonnet 5.5 en effort high pour le code au niveau low [R1]. Côté contexte, rien n'est injecté dans le prompt du modèle principal d'après le README : il ajoute un bandeau d'interface et un panneau `/router`. Hooks : 3 marqueurs [R0].
- **Preuves** : le README le dit lui-même : « Savings are not measured » [R1]. Un ancien essai en mode passerelle, sur un développeur et 26 sessions, donne 15,5 % de moins qu'Opus xhigh permanent et 4,1 % de moins que « le meilleur modèle par session », aux prix catalogue et sans contrôle de qualité [R2]. Le rejeu natif ne trouve que 37 décisions conseillées sur 11 619 et aucune différence de route : il ne permet donc aucune affirmation d'économie [R2]. L'outillage est solide : la sonde d'activité (tableau §1), un contrefactuel « routed vs your model » qui tient compte des lectures et écritures du cache, de la surtaxe Haiku au-delà de 100k et des TTL 5 min / 1 h, vérifié contre le coût que rapporte Claude Code (0,48 $ contre 0,480 $) [R2].
- **Maturité** : créé le 2026-09-22, 34 étoiles, **un seul contributeur**, 100 commits sur 90 jours, v1.15.0 du 2026-10-22, licence MIT [R0]. Il exige Claude Code 2.1.289 ou plus [R1].
- **Risques** : avec Jev, OpenAI ou Clef, le texte du prompt **et celui des tâches de sous-agents** part chez le fournisseur du classifieur (`subagentRouting: off` pour l'éviter) [R1]. Le code JS tourne dans des hooks. Les changements de modèle cassent le cache, ce que la règle de coût du cache est censée limiter. Il entre en conflit avec la méthode en place, où l'orchestrateur et les agents `.claude/agents/` fixent déjà le modèle : les agents qui nomment un modèle ne sont pas routés [R2]. Les agents de workflow non plus, et ils représentaient 22 des 24 sous-agents Opus du mainteneur [R2].
- **Compatibilité Windows** : non indiquée.
- **Verdict** : `Évaluer`. Son contrefactuel de coût et sa sonde valent la lecture, même sans l'adopter. Le routage par tour n'a pas de gain démontré.

### 2.5 Autres API de décision : OpenAI Decisions API, Cloudflare Clef
- OpenAI Decisions API en bêta publique depuis le 2026-10-06, `POST /v1/decisions`, `gpt-6-luna`. L'éditeur annonce une vitesse environ 10 fois supérieure à Responses. Le prix de 0,10 $/Mtok en entrée n'est confirmé que par des tiers [D1]. Cloudflare Clef et Clef Flash sont sortis le 2026-10-01 avec des **poids Apache 2.0** selon des sources secondaires [D1]. Clef est disponible en 27B, 9B et une version Omni 30B MoE sur Workers AI [R1]. Sonde `claude-router` : OpenAI 70/70 avec un p50 de 161 ms, Clef 69/70 avec un p95 de 883 ms [R2].
- **Verdict** : `Évaluer`, comme alternatives à Jev. Clef est la piste « poids ouverts » à suivre si un GGUF apparaît (non vérifié).

### 2.7 Fonctions natives Claude Code (couche de décision intégrée)
- **Auto mode** : un classifieur examine chaque appel d'outil avant exécution. Les actions sûres passent, les risquées sont bloquées et Claude est réorienté. Après des blocages répétés, l'utilisateur reçoit une demande de permission. Disponible pour tous depuis le 2026-07-10. Anthropic ne publie ni taux d'erreur ni modèle utilisé, et recommande des environnements isolés [N1]. C'est l'équivalent natif de la « permission programmable » du PDF, en moins programmable. **Verdict** : `Essayer` (le choix final revient à la dimension revue-sécurité).
- **Advisor (`/advisor`, `advisorModel`)** : expérimental, API Anthropic seulement, abonnement accepté. Claude décide quand consulter un modèle plus fort. Le conseiller reçoit **toute la conversation** et « each advisor call processes the full transcript anew, with no reuse between calls ». Activer ou couper l'advisor ne casse pas le cache principal [N2]. Les tokens sont facturés au tarif d'entrée du conseiller [N2]. **Verdict** : `Essayer` avec Sonnet en principal et Opus en conseiller, mais en mesurant le coût (§3.4).
- **Effort adaptatif** : sur Opus, Sonnet et Haiku 5.5 et Fable 5.1, changer d'effort **garde le cache** avec une clé API ou un abonnement [N3]. C'est le seul routage à coût de bascule nul.
- **`opusplan`** : Opus en mode plan, Sonnet en exécution. Chaque bascule de mode est un changement de modèle avec un cache neuf [N3].
- **Hooks** : un hook `PreModelSwitch` existe pour exiger ou sauter la confirmation de bascule [N3]. `PreToolUse` permet de brancher un classifieur externe sur une commande (mécanisme connu, page hooks non relue ce run, confiance moyenne).
- **Sous-agents avec `model`** : contexte propre, cache froid de 5 min par défaut. Seul le résultat revient dans le fil parent, sans casser son cache [N3].

## 3. Analyse de catégorie

### 3.1 Doublons et complémentarités
- Jev, OpenAI Decisions, Clef et les modèles Ollama exposent **la même primitive** (état + questions typées → probabilités). Ollama a repris le format de Jev [O1]. Aucun n'est strictement meilleur. Jev et OpenAI arrivent premiers sur la sonde synthétique (70/70) [R2]. Ollama est le seul qui garde les données sur le poste, mais il est lent sur un 9B générique (p95 de 3,5 s sur un M2 Pro) [R2]. Nimble et tev1 restent à mesurer sur CPU.
- `claude-router` et `jev-router` font la même chose (modèle et effort par requête) à deux niveaux. `claude-router` reste dans le harnais Claude Code, ce qui préserve l'API Anthropic, l'advisor et le cache. `jev-router` impose une passerelle. Pour Claude Code, `claude-router` est strictement préférable.
- L'advisor natif et le routage par tour s'opposent. L'advisor garde un seul fil principal (cache intact) et paie une relecture non cachée à chaque consultation [N2]. Le routage par tour change de modèle et paie un cache froid à chaque bascule [N3].

### 3.2 Le « piège du routage » face aux mesures
- **Ce que le PDF calcule** : pur Opus 4,15 contre 6,19 pour le chemin routé, aux prix 5/25 et 3/15 [P1]. L'arithmétique est juste. Le modèle est **asymétrique** : le chemin Opus ne paie rien pour relire X, alors que Sonnet paie X au plein tarif d'entrée. Il ne compte ni la lecture du cache ni le nombre de requêtes.
- **Recalcul (ce run)** aux prix officiels 5.5 [N4]. Lecture du cache : 0,20 $ pour Opus et 0,10 $ pour Sonnet (0,05× l'entrée). Écriture 5 min : 5 $ et 2,5 $. Script `calc/piege.py` dans le scratchpad.
  - Même schéma en une passe, avec la lecture du cache côté Opus : 3,68 contre 5,28. **Le piège tient.**
  - Modèle multi-requêtes (X = 150k, Y = 12k de sortie, Z = 40k de lectures, N requêtes) :

    | N requêtes | Opus seul | Basculer le fil principal sur Sonnet puis revenir | Sous-agent Sonnet (contexte 25k, résumé 2k) | Sous-agent Haiku (idem) |
    |---|---|---|---|---|
    | 5 | 0,67 $ | 0,99 $ | 0,37 $ | 0,06 $ |
    | 25 | 1,38 $ | 1,34 $ | 0,48 $ | 0,07 $ |
    | 60 | 2,61 $ | 1,95 $ | 0,65 $ | 0,09 $ |

  - Lecture : basculer le **fil principal** coûte plus cher sur une courte sous-tâche et devient rentable vers 25 requêtes. Un **sous-agent à contexte propre** coûte moins dès la première requête. Le PDF tire la même conclusion (« routing becomes viable only when the harness can hand the cheaper model a small, purpose-built context ») [P1], et c'est le fonctionnement natif des sous-agents [N3]. Hypothèses fortes : même nombre de requêtes et même qualité entre modèles. Le prix de référence ne compte ni le prompt système des sous-agents ni les relances.
- **Mesures publiées** :
  - Claude Code confirme le mécanisme : chaque modèle a son cache, et `opusplan`, une skill avec `model` ou le repli automatique sont autant de changements de modèle [N3].
  - TwinRouterBench modélise le cache (écriture au tarif du niveau entrant à chaque bascule). Un routeur logistique entraîné obtient 75/100 pour 25,66 $ contre 74/100 pour 54,73 $ en Opus seul (−53,1 %). Sur la piste statique de SWE-bench, tous les routeurs ont un gain négatif (« one under-routed step fails the whole trajectory »), et Opus utilisé comme routeur échoue sur les 40 trajectoires [L1]. Préprint de mai 2026 sur 100 cas, avec des modèles 4.6 : confiance moyenne.
  - `claude-router` : −15,5 % contre Opus xhigh permanent, mais un seul développeur, des prix catalogue et aucune qualité mesurée. En rejeu natif, aucune différence [R2].
- **Conclusion provisoire** : le piège est **confirmé pour le changement de modèle dans le fil principal** et pour le routage par étape sans garde-fou. Il est **contredit pour la délégation à contexte réduit**, c'est-à-dire les sous-agents. Le levier sans piège est **l'effort** : même modèle, même cache [N3].

### 3.3 Usages réalistes dans Claude Code (harnais fermé)
1. **Hook PreToolUse « juger une commande »** : une question `noul`/`choice` (allow / ask / deny) posée à un modèle de décision **local** (`tev1:0.8b` ou `tev1` via Ollama), en plus des règles `permissions`. Gain attendu : un filtre de deuxième ligne sans fuite de données. L'auto mode fait déjà ce travail côté Anthropic [N1]. Utile surtout si on n'utilise pas l'auto mode ou pour des règles propres au projet. La latence sur CPU est inconnue.
2. **Orchestrateur, choix Sonnet ou Opus par story** : la décision est rare (une par story) et l'orchestrateur Opus lit déjà la story. Un modèle de décision n'y apporte presque rien en coût. Il peut en revanche **rendre la décision traçable et reproductible**, avec une probabilité et des critères écrits. Faible priorité.
3. **Alerte de dérapage** (agent bloqué, boucle d'échecs) : c'est le cas Codex/effort rapporté par Linas [J6]. Une question `noul` (« l'agent tourne-t-il en rond ? ») posée tous les N tours sur un résumé, avec une action **sur l'effort** qui ne casse pas le cache [N3]. C'est le meilleur candidat à tester.
4. **Appels directs** dans une application (triage, extraction typée) : hors du sujet de l'agent, mais c'est l'usage principal visé par TypeSafe [J2b].
- **Déjà natif** : auto mode, advisor, effort préservant le cache, `opusplan`, `model` par sous-agent ou par skill, hook `PreModelSwitch` [N1][N2][N3].

### 3.4 Problèmes non traités
- **Le coût de l'advisor sur un long transcript n'est pas borné** : aucun réglage pour plafonner les appels [N2]. Avec X = 150k, un appel Opus coûte environ 0,60 $ en entrée (4 $ × 0,15M), soit à peu près 20 tours d'Opus lus en cache (0,03 $ par tour). Aucune mesure publiée ne compare Sonnet + advisor Opus à Opus seul sur des tâches de code.
- Aucun banc **indépendant** des modèles de décision sur des décisions d'agent de code (permissions, détection de blocage, choix de modèle). Les seuls chiffres sont synthétiques (70 prompts) ou viennent des éditeurs.
- La calibration n'est pas garantie hors distribution [J6][O3], or c'est précisément ce qui justifierait un seuil de probabilité.
- La politique de données de TypeSafe n'est pas lue, et aucune politique de rétention n'a été trouvée.

### 3.5 Hypothèses à tester (protocoles courts)
- **H1, effort contre modèle** : sur 3 stories de référence, comparer (a) Opus à effort fixe, (b) Opus avec un effort piloté par un `noul` de dérapage (Ollama `tev1`), (c) Sonnet avec un advisor Opus. Mesures : coût tiré des transcriptions (`mesurer-couts`), nombre de requêtes, tests verts, verdict du reviewer. Critère : (b) ou (c) adoptés seulement si le coût baisse d'au moins 15 % sans verdict reviewer dégradé.
- **H2, juge de commandes local** : rejouer 200 commandes Bash tirées des transcriptions, étiquetées allow / ask / deny à la main, contre `tev1:0.8b`, `tev1` et `nimble` sur le poste CPU 16 Go. Mesures : précision sur les deny, faux deny, p95 de latence. Critère : 0 deny manqué sur les cas dangereux et un p95 sous 500 ms. Sinon, rester sur les règles et l'auto mode.
- **H3, le piège en vrai** : sur une même story, comparer un fil principal qui bascule Opus → Sonnet → Opus et une délégation à un sous-agent Sonnet. Lire `cache_creation` et `cache_read` dans `/usage`. Critère : confirmer ou infirmer le tableau §3.2 à ±30 %.
